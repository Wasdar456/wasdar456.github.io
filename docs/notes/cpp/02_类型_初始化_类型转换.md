# 02 类型、初始化与类型转换

## 列表初始化

原始笔记里关于 `Time t2{2};`、`Time t4 = {21,22,34};` 的说明有价值，整理后统一为下面的规则：

- 花括号初始化属于列表初始化。
- 优点是能阻止窄化转换。
- 如果构造函数被标记为 `explicit`，直接列表初始化通常仍可用，但复制列表初始化要看构造函数形式。

### 原笔记写法

```cpp
Time t2{ 2 };
Time t3 {21,24};
Time t4  = {21,22,34};
Time t5 = {2};
```

### 整理结论

- 这些写法本身是在说明不同初始化形式。
- 真正要注意的是：示例必须和实际构造函数签名匹配，不能想当然地默认存在 `Time(int)` 或 `Time(int,int)`。

## `explicit`

### 核心作用

避免单参数构造函数或可等价为单参数的构造函数触发隐式转换。

### 原笔记想表达的重点

```cpp
Time t1 = 10;   // 不安全的隐式转换示例
```

### 更准确的说法

如果类中存在可接受单个参数的构造函数，上面的写法可能成立；`explicit` 的目的就是阻止这类隐式构造。

## 常见隐式转换

- 基本类型之间的转换，如 `double -> int`
- 单参数构造函数触发的类类型转换
- 运算符重载中为了匹配参数而发生的转换
- 类型转换运算符，如 `operator int()`
- 标准库中从字符串字面量到 `std::string` 的构造

## 考试易错点

- `int x = 9.6;` 可以编译，但会截断。
- `int x{9.6};` 会因为窄化转换报错。
- “能通过编译”和“语义安全”不是一回事。
