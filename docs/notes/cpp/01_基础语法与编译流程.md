# 01 基础语法与编译流程

## 本章定位

这一章收纳最基础但最容易在考试和口头表达里写错的内容：程序构建流程、头文件写法、关键字大小写、基础语法规范。

## 编译与运行流程

常见顺序：

1. `edit`
2. `preprocess`
3. `compile`
4. `link`
5. `load`
6. `execute`

记忆重点：`preprocess` 和 `compiler` 的拼写要写对，原始笔记里这两类单词多次出现过变体，整理后统一用标准写法。

## `#include` 的两种写法

- `#include <...>`
  - 优先找系统或标准库路径。
- `#include "..."`
  - 先找当前工程，再找系统路径。

### 原笔记写法

```cpp
#include <<iomanip>
```

### 修正版

```cpp
#include <iomanip>
```

### 原因

多写一个 `<` 会直接编译错误，这属于考试里很典型的细节失分点。

## 关键字与大小写

C++ 关键字大小写敏感，以下都要统一：

- `do` 不是 `Do`
- `int` 不是 `Int`
- `getline` 不是 `Getline`

## 书写规范

- 每条声明后面要补分号。
- 初始化列表、函数声明和类定义里，尽量保持一行一义。
- 演示代码允许短，但不要省略会导致语法错误的符号。

## 从原始笔记转来的提醒

- 不要把“能猜出意思”和“能编译通过”混为一谈。
- 课堂记笔记时，若是老师口头解释，可以先记要点；回写正式笔记时必须补成合法代码。
