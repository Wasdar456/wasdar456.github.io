# 08 运算符重载与拷贝控制

## 运算符重载基本原则

- 语法形式是 `operator+`、`operator<<` 这类函数名
- 可以写成成员函数，也可以写成非成员函数
- 不会凭空改变优先级、结合性和操作数个数

## 成员函数写法 vs 非成员写法

### 成员函数

```cpp
Complex operator+(const Complex& rhs) const;
```

### 非成员或友元

```cpp
friend ostream& operator<<(ostream& os, const Time& t);
```

## 关系运算符

建议成对实现，避免只重载一半导致行为不一致。

## 浅拷贝风险

原始笔记里“复制成员内容时复制了内存”这一段，整理成更准确的说法：

- 默认拷贝赋值是逐成员拷贝
- 如果类里有动态内存指针，默认行为往往只是复制地址
- 这会带来内存泄漏、重复释放和数据污染

## 深拷贝赋值运算符

```cpp
MyString& MyString::operator=(const MyString& other) {
    if (this == &other) {
        return *this;
    }

    delete[] str;
    str = new char[strlen(other.str) + 1];
    strcpy(str, other.str);
    return *this;
}
```

## 刷题中的类设计启发

原始草稿里提到 `Time` 用 `totalSec` 存总秒数，这种写法的好处是：

- 内部状态单一
- 运算符重载更简单
- 格式化输出时再拆回时分秒

这属于很典型的“内部表示简化外部接口”的设计思路。
